## 2. Tổ chức mã theo thành phần

Bố cục cài đặt dùng đúng chín package của DOC 6.1-A §3 và các thành phần P/B/D/X/J trong DOC 5.1-A/B. Cấu hình DOC 7.4-B quản lý `src` và `tests`.

```text
backend/
├── src/tomateto/
│   ├── presentation/       P1–P4: resolver, HTTP endpoint, ContextFactory, ErrorMapper, mapper
│   ├── contract/           input, output, ApiError, FieldError
│   ├── business/           B1–B10: service, policy, factory và các lớp hỗ trợ
│   ├── dataaccess/         D1–D4: repository và ánh xạ persistence
│   ├── integration/        X1–X4: ports và adapters lưu ảnh, email, push, AI
│   ├── domain/             entity, enum, value object và ngoại lệ nghiệp vụ
│   ├── shared/             Config, Clock và TransactionManager
│   ├── worker/             J1: BackgroundJobRunner, lịch và khóa job
│   └── bootstrap/          AppContainer, RequestScope và WorkerScope
└── tests/
    ├── unit/               service, thuật toán, mapper và policy với dependency giả
    └── integration/        HTTP/GraphQL, repository thật và dịch vụ ngoài giả lập
```

- Resolver/endpoint nhận input và principal, gọi service, chuyển kết quả thành DTO. Ví dụ `MediaUploadEndpoint` gọi `PostLifecycleService`. Service kiểm quy tắc trước khi gọi repository/adapter.
- Service sở hữu ranh giới transaction. Repository truy xuất dữ liệu trong phiên được cấp. DTO mapper nhận dữ liệu đã nạp. Ví dụ `PostMapper` dùng danh sách ảnh đã nạp theo lô, không gọi thêm query cho từng bài.
- API dùng phiên đồng bộ theo request. J1 mở phiên riêng từng job. Job định kỳ gọi service. Ví dụ `cleanup_orphan_media` nhận việc theo cơ chế khóa đã chốt, nhả transaction trước khi gọi kho ảnh và ghi kết quả sau.
- Adapter nhận cấu hình lúc khởi tạo. Ví dụ `AiAdapter` đọc endpoint và khóa qua `Config`. `AssistantService` gọi cổng tích hợp. Dùng stub của cổng đó để kiểm timeout và fallback.
- `User` và `Post` thuộc `domain/entity`. `DomainError` và `ValidationError` đặt ở `domain/errors.py` theo quy ước cài đặt. `ApiError`, `FieldError` là kiểu truyền ở biên API, đặt trong `contract/error`. `ErrorMapper` ở `presentation` chuyển ngoại lệ sang các kiểu này. `bootstrap` lắp các lớp vào scope, rồi tầng dưới nhận dependency qua constructor.

## 5. Bảo mật

- **Input và quyền.** Validate tại biên và kiểm quy tắc nghiệp vụ bằng principal từ JWT. `updatePost` kiểm owner trước khi ghi. Feed, search và trợ lý lọc block hai chiều trước phân trang/tra tham chiếu. DTO công khai dựng theo danh sách trường được phép.
- **SQL injection và XSS.** Truyền từ khóa tìm kiếm qua tham số bind SQLAlchemy. Trả caption/bio là dữ liệu chuỗi JSON, giữ cách hiển thị dạng văn bản ở client. Khi có ngữ cảnh HTML đã duyệt, dùng cơ chế escape hoặc sanitize phù hợp với ngữ cảnh đó.
- **Bí mật và truyền tải.** `Config` đọc khóa ký JWT, DB và provider từ biến môi trường. Chỉ dùng giá trị giả trong cấu hình mẫu và test. Reverse proxy phục vụ HTTPS khi triển khai công khai. Ví dụ lỗi gọi AI ghi request ID, mã lỗi và thời lượng đã lọc.

## 6. Hiệu năng và tài nguyên

- Feed dùng keyset, mặc định 10 và giới hạn 50. Lấy ảnh và trạng thái like/lưu theo lô cho trang hiện tại. Đo p95 khi thay đổi truy vấn theo DOC 7.3-A và đọc `EXPLAIN` cùng DB nếu chậm.
- Giữ `run_id` trong cursor TRENDING để các trang đọc cùng snapshot. Nếu tái dùng kết quả đã tính, chỉ tái dùng dữ liệu theo run còn hợp lệ và vẫn áp quyền theo viewer khi đọc. Dùng `Clock` để kiểm thời điểm job công bố snapshot mới.
- Đóng phiên và connection theo request/job scope. Đặt timeout cho adapter, bao gồm toàn bộ lần gọi và thời gian chờ trong ngân sách 30 giây của trợ lý. Chỉ gọi provider sau khi đã nhả transaction phù hợp với luồng.

## 8. Mẫu Python để kiểm tra

Lưu mẫu thành `page_lint_example.py` cạnh `pyproject.toml` của DOC 7.4-B. Chạy `ruff check --config pyproject.toml page_lint_example.py`, `ruff format --check --config pyproject.toml page_lint_example.py` và `mypy --config-file pyproject.toml page_lint_example.py`. Mẫu dùng hai lớp ngoại lệ rút gọn để chạy độc lập. Khi triển khai, import các lớp dùng chung ở `domain/errors.py`. Resolver bắt `DomainError` và chuyển cho `ErrorMapper`. Với `first=0`, phản hồi HTTP 200 có `extensions.code=VALIDATION_FAILED` và `fieldErrors` chứa `page.first`/`PAGE_SIZE_INVALID`. Với `first=100`, kích thước hiệu lực là 50.

```python
DEFAULT_PAGE_SIZE = 10
MAX_PAGE_SIZE = 50


class DomainError(Exception):
    """Represent an application error for the presentation layer."""


class ValidationError(DomainError):
    """Carry the safe message and field details for ErrorMapper."""

    code = "VALIDATION_FAILED"

    def __init__(self, field: str, field_code: str, message: str) -> None:
        super().__init__(message)
        self.field = field
        self.field_code = field_code


def normalize_page_size(first: int | None) -> int:
    """Default or clamp the page size, and reject nonpositive input."""
    if first is None:
        return DEFAULT_PAGE_SIZE
    if first <= 0:
        raise ValidationError(
            "page.first",
            "PAGE_SIZE_INVALID",
            "Số lượng mục mỗi trang không hợp lệ.",
        )
    return min(first, MAX_PAGE_SIZE)
```
