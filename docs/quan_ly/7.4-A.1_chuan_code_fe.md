## Cấu trúc và đặt tên

Trong dự án Flutter, `lib/core/` chứa transport, phân trang và kiểu lỗi. Các nhóm `session/`, `content/`, `social/`, `discovery/` chứa View, Controller và Repository theo chức năng. `test/` phản ánh cấu trúc lớp cần kiểm. `integration_test/` chứa các luồng nối nhiều màn. Ví dụ `content/post_editor_controller.dart` chứa `PostEditorController`, method `submitCreate` và trường riêng `_repository`. File dùng snake_case, kiểu dùng UpperCamelCase, biến và method dùng lowerCamelCase. Provider có hậu tố `Provider`, chẳng hạn `postEditorProvider`.

## Phân tích tĩnh

Dùng `flutter_lints` và bật `strict-casts`, `strict-raw-types`. Mỗi method có kiểu trả rõ, ví dụ `Future<void> loadFeed()`. Dùng `final` cho repository hoặc kết quả không gán lại, `const` cho widget và giá trị cố định. Dùng dấu phẩy cuối khi gọi constructor nhiều dòng. Chờ tác vụ bằng `await` khi cần kết quả. Khi chủ đích chạy nền, dùng `unawaited` và bắt lỗi ngay trong tác vụ được gọi, như `loadFeed` trong mẫu. Chỉ cập nhật lỗi lên state nếu lượt gọi còn thuộc generation hiện tại. Sau `await`, kiểm tra `mounted` trước khi dùng `BuildContext`. Hủy subscription và đóng sink khi kết thúc vòng đời. `avoid_print` áp dụng cả khi gỡ lỗi. Chạy `flutter analyze` từ thư mục dự án Flutter cùng cấu hình của Lead.

## Xử lý dữ liệu và lỗi

View gửi ý định, Controller cập nhật state và Repository ánh xạ hợp đồng API. Ví dụ `PostEditorController` giữ form và trạng thái ảnh, còn Repository dựng yêu cầu `createPost`. Với GraphQL, Mapper phân loại lỗi từ `errors` kể cả HTTP 200. Mapper đọc `errors[].extensions.code` để phân loại và `errors[].extensions.fieldErrors` để chuyển lỗi về đúng trường, chẳng hạn lỗi của `dishName` hiển thị dưới ô tên món. Lỗi không khớp trường đang có được hiển thị ở đầu form. Với `RATE_LIMITED`, đọc số giây nguyên không âm từ `errors[].extensions.retryAfterSeconds` nếu có. Khi lỗi gửi lại OTP thiếu giá trị này, chỉ hiện thông báo giới hạn và không tự đặt bộ đếm. Trường `data.resendResetOtp.retryAfterSeconds` nếu có thuộc phản hồi thành công. Giữ `requestId` để đối chiếu khi cần. Chọn thông báo tiếng Việt theo DOC 7.2-A. Log chỉ giữ operation, mã lỗi và requestId phù hợp. Token, OTP, mật khẩu và dữ liệu riêng tư phải được lọc trước khi ghi. Khi mất phản hồi đăng bài, giữ trạng thái chưa xác nhận để đối soát. Sau đổi phiên, bỏ kết quả của tài khoản cũ.

## Ví dụ đúng và sai trong ToMateTo

| Tình huống | Đúng | Sai |
|---|---|---|
| Kiểu trả về | `Future<void> loadFeed()` | `loadFeed()` thiếu kiểu trả |
| Phạm vi của View | View gọi `controller.submitCreate()` | Widget tự gửi GraphQL `createPost` |
| Cấu trúc dữ liệu lỗi | Kiểm `errors` trong HTTP 200 | Gán thành công chỉ theo status 200 |
| Session | Controller bỏ response của phiên cũ | Callback cũ ghi vào feed của tài khoản mới |
| Log khôi phục | Ghi operation, requestId và mã lỗi | Ghi email kèm OTP hoặc token |
| Điều hướng sau await | Kiểm `context.mounted` rồi mới điều hướng | Dùng context sau khi màn đã bị hủy |
| Repository | `final ContentRepository _repository` | Cho thay `_repository` tùy ý trong lúc gửi bài |
| Tạo bài mất phản hồi | Giữ bản soạn và đối soát `myPosts` | Tự gọi lại `createPost` khi mạng trở lại |

## Mẫu Dart để kiểm tra

Đặt mẫu sau vào `lib/feed_lint_example.dart` tại dự án Flutter có cấu hình 7.4-B và dependency `flutter_lints`, rồi chạy `flutter analyze lib/feed_lint_example.dart`. Mẫu kiểm cùng generation ở cả nhánh thành công và nhánh lỗi. Khi phiên đổi, tầng quản lý phiên làm mới provider theo phiên hoặc gọi `reset()` nếu controller được giữ lại. Khi đổi bộ lọc, handler của màn khởi động lượt tải mới để tăng generation. Nếu muốn xóa danh sách cũ ngay lúc đổi bộ lọc, gọi `reset()` trước lượt tải mới. Ví dụ sau khi đăng xuất, lỗi mạng từ request feed của tài khoản cũ không xuất hiện trên màn hiện tại.

```dart
import 'dart:async';

abstract interface class ContentRepository {
  Future<List<String>> fetchFeed();
}

final class FeedController {
  FeedController(this._repository);

  final ContentRepository _repository;
  int _generation = 0;
  List<String> _items = const <String>[];
  String? _error;

  List<String> get items => _items;
  String? get error => _error;

  void refreshInBackground() {
    unawaited(loadFeed());
  }

  Future<void> loadFeed() async {
    final int generation = ++_generation;
    _error = null;
    try {
      final List<String> response = await _repository.fetchFeed();
      if (generation == _generation) {
        _items = List<String>.unmodifiable(response);
      }
    } on Object {
      if (generation == _generation) {
        _error = 'Chưa tải được dữ liệu.';
      }
    }
  }

  void reset() {
    _generation++;
    _items = const <String>[];
    _error = null;
  }
}
```
