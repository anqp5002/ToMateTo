## 1. Phạm vi và cách dùng

Đây là DDL tham chiếu để review S5, không phải migration Alembic hoặc script nâng cấp DB đang có dữ liệu. Khối DDL dưới là nguồn SQL duy nhất của tài liệu; COMMENT giữ ý nghĩa cột trong catalog. Chỉ chạy trên database thử nghiệm trống. Việc chạy thành công không giải quyết các mâu thuẫn API/FR tại C01–C10.

Ngày 31/10/2026, người yêu cầu xác nhận giữ ba bảng Tag trong bản thiết kế để khớp DOC 5.3; xem DOC 6.4-A mục 1. DDL tiếp tục có đủ 25 bảng. Phê duyệt triển khai chức năng Tag vẫn chờ team xử lý C01.

Yêu cầu PostgreSQL 16, UTF-8, schema public trống; vai trò thử nghiệm có quyền tạo bảng và extension pg_trgm/unaccent. Không nhúng tài khoản/mật khẩu DB thật. Migration owner và quyền runtime tối thiểu được cấu hình ở lát cài đặt; không suy ra rằng API sẽ dùng superuser.

DDL có BEGIN/COMMIT, tạo bảng theo thứ tự phụ thuộc; users→media được ALTER sau. Không dùng IF NOT EXISTS cho bảng để tránh che schema cũ không khớp. Extension đã tồn tại phải ở public; kiểm môi trường thay vì âm thầm dùng extension ở schema khác.

Tên constraint/index dùng snake_case để nhận biết lỗi. SQLSTATE 23505 là UNIQUE, 23503 là FK, 23514 là CHECK, 23502 là NOT NULL; BE phải dịch thành lỗi nghiệp vụ, không trả SQL/giá trị bí mật ra API.

UNIQUE vị trí ảnh là DEFERRABLE INITIALLY IMMEDIATE; các thao tác đổi thứ tự chủ động defer đúng constraint, còn thao tác thường vẫn kiểm ngay. Không dùng constraint deferred đó làm arbiter ON CONFLICT; upsert like/follow dùng PK không deferred. Tham khảo [CREATE TABLE PostgreSQL 16](https://www.postgresql.org/docs/16/sql-createtable.html).

    social_links JSONB DEFAULT '{}'::jsonb NOT NULL,
    public_profile_fields TEXT[] DEFAULT '{}'::text[] NOT NULL,

    token_version INTEGER DEFAULT 0 NOT NULL,
    is_active BOOLEAN DEFAULT true NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,

    CONSTRAINT pk_users PRIMARY KEY (id),
    CONSTRAINT uq_users_email_normalized UNIQUE (email_normalized),
    CONSTRAINT uq_users_username_normalized UNIQUE (username_normalized),

    CONSTRAINT uq_users_cover_media_id UNIQUE (cover_media_id),
    CONSTRAINT ck_users_username_pair CHECK ((username IS NULL) = (username_normalized IS NULL)),
    CONSTRAINT ck_users_display_name CHECK (btrim(display_name) <> ''),

## 3. Thực thi và phục hồi khi kiểm tra

1. Trích nguyên khối giữa BEGIN DDL/END DDL thành schema.sql UTF-8; khối BEGIN SMOKE/END SMOKE thành smoke.sql.
2. Tạo database thử nghiệm mới. Chạy `psql -X -v ON_ERROR_STOP=1 -d <test_database> -f schema.sql`.
3. Chạy `psql -X -v ON_ERROR_STOP=1 -d <test_database> -f smoke.sql`. Các lệnh cố ý sai được bắt theo SQLSTATE; lỗi ngoài kỳ vọng dừng kiểm tra.
4. Smoke kết thúc bằng ROLLBACK, không giữ fixture hay function kiểm tra. Giá trị sequence đã lấy không được rollback, nên đây không phải seed sản phẩm.
5. Nếu DDL lỗi trước COMMIT, transaction bị hủy; không bỏ qua lỗi rồi chạy tiếp từng phần. Nếu đã COMMIT và muốn thử lại, dùng database thử nghiệm mới. Không dùng DROP CASCADE trên database dự án để “sửa” lỗi.
6. DDL này không phải downgrade. S8+ xây Alembic theo từng lát, kiểm upgrade/downgrade và bảo toàn dữ liệu riêng; các quyết định phạm vi phải được giải quyết trước khi tạo migration.

Có thể trích hai khối bằng Python từ thư mục gốc repo; chỉ tạo file trong thư mục tạm của hệ điều hành:
